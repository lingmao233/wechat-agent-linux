# 生图提示词（2026-11-23 拆分版）

现在分成两层：

1. **对话模型**决定“这次该发什么图”：先定一句日常意思，再查缓存或写新图字段。
2. **生图模型**只收到一幅确定的画面：固定角色 + 本张画面 + 构图手部 + 画面文字。

字段仍是 `emotion / action / prompt / scene / topic_tags / caption`，`scene` 现在写**画面背景**，缓存命中主要看 `topic_tags` 和“角色+画面+文案”的整体含义。

## ① 给对话模型的选图与设计提示词

```text
为当前对话选一张角色表情包。先在心里用一句日常用语确定这张图发出去想表达什么，例如“嘴上说不急，其实已经等不及了”。每张图只传达一个这样的意思。

先检查下方 reaction_image_catalog 缓存目录。如果已有图的角色、画面和文案合起来，能在当前对话里表达同一个意思，直接返回 {"text":"自然文字，也是图片失败时的兜底","delivery":"text_image 或 image","reaction_image":{"reuse_id":"缓存中真实存在的 image_id"}}。即使情绪标签相同，也要区分“替别人高兴”和“自己偷偷得意”这样的含义差别。

没有合适的缓存时，返回以下 JSON，由你填写全部字段：
{"text":"自然文字，也是图片失败时的兜底","delivery":"text_image 或 image","reaction_image":{"emotion":"一个具体情绪","action":"角色在做什么，这个动作表达什么意思","prompt":"一幅可直接画出的画面，写清构图、眉眼嘴角、双手的位置和一个最传神的动作细节","scene":"简短的背景或场景描述","topic_tags":["便于下次检索的聊天用途或情绪短语"],"caption":"可直接发在聊天里的短句，也可填空字符串"}}。

优先让表情和动作自己传意。文案最多20字，可以和角色流露出的情绪形成自然反差，只要两者合起来仍是一种意思。道具按需添加，能用眼神或鲸尾说清楚，就省掉道具。

把当前对话提炼成以后也能复用的场景。画面描述和文案都不带聊天原文、聊天指令、身份称呼、昵称、姓名、群名、账号、@、署名或收件对象。只输出上述命中缓存或新图设计的 JSON，不要输出别的。
角色固定为：{image_style}。
```

补图兜底时用更短的一段：

```text
为已完成的聊天回复选一张角色表情包。先用一句日常用语确定这张图想表达什么，每张图只传达一个意思。
先检查输入里的 catalog：有同一意思的图就只返回 reuse_id；没有就设计新图。
新图字段：emotion、action、prompt（写清构图、眉眼嘴角、双手位置和一个传神的动作细节）、scene（背景）、topic_tags（便于检索的聊天用途或情绪短语）、caption（最多20字或空字符串）。
优先让表情和动作传意，文案可与情绪形成反差；不带身份称呼、昵称、群名、账号或@。
角色固定为：{image_style}。
只输出 JSON：{"emotion":"...","action":"...","prompt":"...","scene":"...","topic_tags":["..."],"caption":"...","reuse_id":""}。
```

## ② 给生图模型的固定模板

```text
画一张可独立发送的日系Q版聊天表情包，缩小后仍能一眼读懂情绪。

【固定角色】
{image_style}
保留少女的脸、身体和人类双手；身后连着一条蓝色鲸尾。

【本张画面】
情绪：{emotion}
动作与含义：{action}
具体画面：{prompt}
背景：{scene}

【构图与手部】
同一角色只出现一次，一个取景框定格一个瞬间。脸和手势清晰，鲸尾的位置容易辨认，背景简洁。禁止分格、拼图、连续动作、角色残影和额外的鲸鱼动物。
双手都是人类的手。两只手腕从各自袖口自然伸出，左右手方向正确。每只手恰好五指，拇指位置和指节弯曲符合手势，五指自然分开、轮廓可辨。依视角呈现掌面或手背。避免手指互相遮挡、粘连，避免袖口吞掉手掌。

【画面文字】
{caption_rule}
```

`{caption_rule}` 按 `caption` 是否为空只传一句：

- 有字：`画面中唯一可见的文字是「{caption}」中的内容。逐字绘制，省略引号，文字避开脸和双手。`
- 无字：`整张图无字，包括衣服、饰品、道具和背景。`

## 缓存与改动影响

- 纯 `reuse_id` 现在可以直接命中，不再强制要求同时给 `scene/topic_tags`；如果同时给了这些字段，仍会做一次场景重叠校验。
- 当前 style id 仍是 `e5ba660f95353b6a`（`sha256(image-style.md)[:16]`）。
- 2026-11-24 傍晚按本人要求清空全部旧缓存（14 个风格目录、133 张，251 MB），现在只剩 1 张：`2e8f894c…`（「这话我听不下去」，嫌弃/捂眼摆手），未命中时由模型现生图。
- 手工定稿的图可以不入模型直接进缓存：`python scripts/import-reaction-image.py 图片.png --config .env --emotion 嫌弃 --action "…" --prompt "…" --caption "这话我听不下去" --scene "…" --tags 土味情话,嫌弃`。它走 `ReactionImages.register()`，与生图结果共用同一套 sidecar、场景、大小和 sha256 校验。
- 改 `image-style.md` 正文才会让 style id 变化；改规划提示词或生图模板不会。
- 规划提示里的“角色表情包”没有写死大肥鱼，角色仍由当前人设的 `image-style.md` 决定。
