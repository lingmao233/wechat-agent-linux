# 漫剧/短剧角色配音：情绪与语速的开源方案调研（2026-11-25）

本机环境：VM 无 GPU（2 vCPU / 7 GB），所以"本地常驻推理"不是首选；结论按"云端 API 为主、离线 GPU 为辅"给出。

## 一、漫剧/短剧配音实际怎么处理情绪和语速

看下来是三条流水线，常混用：

1. **角色音色 + 情绪参考（最主流）**
   先给角色训练/复刻一个音色，再按每句的情绪**换参考音频**：高兴用一段笑的参考、生气用一段吼的参考，模型跟着参考的韵律走。
   代表：GPT-SoVITS（1 分钟数据克隆 + 参考音频决定情绪）、IndexTTS2（把"音色"和"情绪"彻底解耦，可分别指定）。

2. **指令/标签控制**
   不换参考音频，而是在文本或参数里写情绪标签、语速档位、停顿。
   代表：CosyVoice（instruct 指令、情感标签、停顿标记）、EmotiVoice（emotion prompt）、Spark-TTS（gender/pitch/speed 属性 token）、FireRedTTS3（instruction-guided 音色设计）、MOSS-TTS（`[pause X.Ys]` 显式停顿）。

3. **音色后置换（TTS + RVC）**
   先用普通 TTS 生成"有情绪、语速对"的语音，再用 RVC 把音色换成角色，**保留原语音的情绪、节奏、停顿**。B 站大量"AI 配音"教程就是 `TTS → RVC` 这条链。
   代表：RVC-Project/Retrieval-based-Voice-Conversion-WebUI。

另外，真要"对口型、卡时长"的影视级配音，还有专门的多模态配音模型：FunCineForge（时间模态 + 唇形 + 情绪）、FireRedTTS2（多说话人长对话）、IndexTTS2（token 级精确时长）。

## 三、和我们现在实现的对应关系

我们已经做的（`src/wechat_agent/voice_style.py`）：

- 7 类风格枚举 + 语速倍率 → 等价于 **Spark-TTS 的 speed 档位 + IndexTTS2 的情绪软指令**；
- `instruction` 拼接 → 等价于 **CosyVoice instruct**；
- 标点/关键词规则兜底 → 等价于 **gpt_sovits_infer_with_emotion 的情绪分类切参考音频**。

还缺的三块：

1. **情绪参考音频**：IndexTTS2/GPT-SoVITS 能做到"用 A 的音色 + B 的情绪"，我们只有文字指令。
2. **精确时长/停顿**：MOSS-TTS 的 `[pause]`、IndexTTS2 的 token 时长，我们只能靠语速倍率粗调。
3. **音色后置换**：RVC 能把任意一条 TTS 换成角色音色且保留情绪，正好解决"社区阿楚模型不像、但原声又拿不到"的问题。

## 四、可落地的路线（按成本排序）

**A. 零成本（今天就能做）**
在现有 `voice_style.py` 上扩到 10 类，并给每类加"停顿/拖音"模板：句末加「……」拉长、逗号处插 0.2s 静音，效果接近 MOSS-TTS 的 pause 控制。改的是提示词和一张表，不动架构。

**B. 低成本（几百块以内）**
租一张按小时的 GPU（或借本机显卡）跑 IndexTTS2/EmotiVoice，离线生成"阿楚音色 + 指定情绪"的 10–20 秒参考音频，再上传阿里云做音色复刻。这样云端调用的仍是阿里云，但音色和情绪基线来自更强的模型，绕开社区模型质量差的问题。

**C. 中成本（需要一台 GPU 常驻）**
本地起 CosyVoice3/IndexTTS2 服务 + RVC 后处理，替换云 TTS。延迟、运维、显存都是成本；适合以后要做漫剧成片配音，不适合现在这个聊天场景。

**D. 面向漫剧成片**
真要"音画同步、唇形对得上"，走 FunCineForge / FireRedTTS2 / IndexTTS2 时长控制这条线，和聊天机器人是两套系统。

## 五、深入对比（README / 官方仓库实测参数）

### 5.1 情绪与语速到底怎么传进去

| 项目 | 情绪怎么控制 | 语速怎么控制 | 接口形态 | 资源 |
|---|---|---|---|---|
| **IndexTTS-2.5**（index-tts） | ① 单独一段情绪参考音频 `emo_audio_prompt` + 强度 `emo_alpha(0–1)`；② 8 维情绪向量 `emo_vector=[happy,angry,sad,afraid,disgusted,melancholic,surprised,calm]`；③ `use_emo_text` 从正文自动推断；④ `emo_text` 用另一句话描述情绪 | **`duration_factor` 0.5–2.0**（>1 变慢），直接控时长 | Python API、WebUI、vLLM 部署 | 0.8B 参数，4090 上 RTF≈0.2，fp16/BF16 可省显存 |
| **GPT-SoVITS**（bilibili） | 只能靠**换参考音频**；v3/v4 情绪更丰富但无参数 | **没有语速参数**（官方 Todo 里还写着"TTS speaking speed control"未完成） | WebUI + `api.py` / `api_v2.py`（HTTP） | 5 秒零样本、1 分钟微调；4060Ti RTF 0.028、4090 0.014、M4 CPU 0.526 |
| **Fun-CosyVoice3-0.5B**（CosyVoice） | **instruct 指令**：情绪、方言、语言、音量都能写进指令 | **instruct 里带 speed** | `example.py`、FastAPI / gRPC runtime、vLLM / TensorRT-LLM | 0.5B 参数，150ms 双流式，9 语言 + 18 种方言 |
| **EmotiVoice**（网易有道） | 情绪 prompt（happy/sad/angry 等） | 无独立语速参数 | Docker + **OpenAI 兼容 API** + Streamlit | 2000+ 音色，Apache-2.0 |
| **RVC**（RVC-Project） | 不控情绪，**保留输入音频的情绪与节奏** | 跟随输入音频 | WebUI + CLI | ≤10 分钟数据训练，MIT |
| **FireRedTTS3** | instruction-guided 音色设计 + 语音编辑 | 语音编辑里改 | Python | 1.7k stars，Apache-2.0 |
| **MOSS-TTS**（8B） | 上下文韵律 | **`[pause X.Ys]` 显式停顿** | Python | 8B，吃显存 |

结论一句话：**IndexTTS-2.5 是唯一把"情绪"和"语速"都做成显式参数的开源模型**；CosyVoice3 用自然语言指令同时覆盖两者；GPT-SoVITS 音色最像，但情绪和语速都得靠参考音频"带"出来。

### 5.2 许可证与商用

- IndexTTS：**bilibili Model Use License Agreement**（非标准），商用要联系 `user@example.com`。
- GPT-SoVITS / RVC：MIT。
- CosyVoice / EmotiVoice / FireRedTTS3：Apache-2.0。
- 社区音色（Fish 上的角色模型）：随时可能下架，授权不可控。

### 5.3 接入我们这套代码的成本

- **CosyVoice3 / EmotiVoice**：自带 HTTP 服务（FastAPI / OpenAI 兼容），我们可以直接加一个 `local_http` provider，改动量和当初加 `fish` 差不多（一个 provider 文件 + 注册 + 测试）。
- **IndexTTS-2.5 / GPT-SoVITS**：只有 Python API 或自带 api.py，需要包一层 HTTP 服务（约 100 行 FastAPI），再接进来的方式和上面一样。
- **RVC**：放在 TTS 之后做后处理，属于"音频二次加工"，可以在发送前加一步，也可以离线批量做音色样本。

## 六、风险

- **许可证**：GPT-SoVITS / RVC 是 MIT，CosyVoice / EmotiVoice / FireRedTTS3 是 Apache-2.0；IndexTTS2 是非标准许可证，商用前必须自查。
- **角色音色版权**：社区模型和"复刻真人/角色"都有授权风险，私下用和对外发布是两回事。
- **模型下架**：Fish 上的社区音色随时可能被作者删除，线上音色不要只依赖一个社区模型。
- **GPU 现实**：当前 VM 无 GPU（`nvidia-smi` 不存在，2 vCPU / 7 GB），任何本地推理都要另找机器。
