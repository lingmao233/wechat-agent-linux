# 抖音桥架构与扩展指南

> 面向“我要给抖音桥加一个功能”的快速上手文档。先看第 1–3 节建立地图，再按第 6 节的流程动手。

## 1. 它是什么

`src/wechat_agent/douyin_bridge/` 是一个独立子系统：用 Playwright 驱动一个**无头** Chromium 打开 `douyin.com/chat`，轮询绑定的抖音私信会话，把媒体（表情、视频、图集）转发到对应微信联系人；反向读取微信联系人的表情/命令，转发回抖音。它跑在控制台（`wechat_agent desktop`）进程里，和微信聊天 Agent 共用同一个后端。

## 2. 文件地图（按“改哪里”理解）

| 文件 | 行数级 | 职责 | 什么时候改 |
|---|---|---|---|
| `service.py` | 3k+ | 总调度：轮询循环、任务队列 worker、抖音↔微信两个方向的处理、看门狗、状态接口 | 加业务分支、新任务类型、新 API |
| `chat.py` | 2k | 抖音网页 DOM 操作：会话列表、打开会话、身份校验、读消息、发文字/媒体、页面恢复 | 抖音页面改版、选择器失效、新增读取字段 |
| `binding.py` | 150 | 绑定关系（抖音会话名 ↔ 微信 wxid） | 绑定规则变更 |
| `intent.py` | 250 | 命令/意图解析：`转微信`、`转抖音`、点歌、状态查询等 | 加新命令、新关键词 |
| `media.py` | 300 | 媒体下载、格式识别、WebP/GIF 转微信原生表情、视频/图集落盘 | 新格式、转码规则 |
| `delivery.py` | 130 | 微信发送适配层（OutboundAction → backend.send，强制回读核验） | 新发送方式（语音、文件、引用） |
| `dtk.py` | 600 | 第三方 DTK 解析服务客户端（抖音/视频解析） | 解析源、重试策略 |
| `store.py` | 700 | 持久化（SQLite）：任务、绑定、已读指纹、微信游标 | 新表、新查询 |
| `models.py` | 300 | 路由/消息数据类 + 桥自己的 ORM 表 | 新数据结构 |

上游依赖：`config.py`（`douyin_bridge_*` 配置）、`desktop.py`（控制器 wiring + `/api/douyin-bridge*` 路由 + 设置项）、`agent.py`（启动/停止时 attach 后端）、`platforms/browser.py`（Playwright 浏览器适配层）、`bilibili.py`（B 站视频下载）。

## 3. 运行时结构

- **一个浏览器、一个线程**：所有 Playwright 调用都在桥自己的事件循环线程里，`service.call_in_loop()` 是唯一入口；**不要在别的线程直接调 `chat.*`**。
- **轮询线程**：每 `DOUYIN_BRIDGE_POLL_SECONDS` 秒遍历启用的绑定 → 打开会话 → 校验当前会话标题 → 读取消息 → 对新消息建任务。
- **任务队列**：任务落 SQLite（`douyin_bridge_jobs`，状态 `detected→ready→processing→delivered/failed/uncertain`），后台 worker 串行处理，微信界面同一时刻只允许一个发送者（`SEND_BUSY` 会回队重试，最多 8 次）。
- **发送与回读**：`WeChatDelivery` 只调用 `backend.send()`，必须通过微信数据库回读核验才算成功；不确定（uncertain）不自动重发。

### 抖音 → 微信（主链路）
```
poll_loop
  → open_conversation(peer)          # 点击会话并校验标题，失败跳本轮
  → read_messages()                  # 返回 index/kind/direction/fingerprint/row_text
  → 新消息判定（douyin_bridge_seen 指纹去重）
  → _create_transfer_job()           # kind = sticker | video | album | text
  → worker: _process_job()
      → _prepare_sticker/_prepare_video/_prepare_album   # media.py 下载+转码
      → 表情：store_image_bytes → sticker_gif_for_wechat → deliver_file（微信收成原生表情）
      → 视频/图集：落盘 → deliver_file/image → 微信原样投递
      → 回读核验 → 成功删媒体、写 ledger
```

### 微信 → 抖音（反向）
```
poll_wechat → 读绑定 wxid 新消息 → 表情/显式命令(intent.py)
  → fetch_sticker / 媒体 → douyin chat.send_* → 回执可选
```

## 4. 数据表（都在桥的 models.py / store.py）

- `douyin_bridge_bindings`：`peer_name`（抖音会话名）↔ `wxid`（微信联系人），`status`
- `douyin_bridge_jobs`：任务（kind/status/source_fingerprint/media_path/media_sha256/mime/target_wxid/delivered_ids）
- `douyin_bridge_seen`：消息指纹去重（避免轮询重复建任务）
- `douyin_bridge_baselines`：每个会话的“只处理开启之后的新消息”截止时间
- `douyin_bridge_wechat_cursors`：微信侧读取游标
- `douyin_bridge_codes`：解析码/临时凭证

改表结构时：先改 `models.py`，再确认 `BridgeStore` 初始化会 `create_all`；VM 上已有数据，新增列要兼容旧库（可空或有默认值），必要时写一次性迁移脚本，**不要 drop 表**。

## 5. 关键配置（`.env` → config.py）

- 开关：`DOUYIN_BRIDGE_ENABLED`（桥总开关）、`DOUYIN_BRIDGE_WECHAT_ENABLED`（反向转发）、`DOUYIN_BRIDGE_REPLY_ENABLED`、`DOUYIN_BRIDGE_CHAT_ENABLED`
- 频率/上限：`DOUYIN_BRIDGE_POLL_SECONDS`、`MAX_JOBS_PER_HOUR`、`MAX_VIDEO_MB`、`MAX_STICKER_MB`、`MAX_ALBUM_IMAGES`、`CONTEXT_SECONDS`、`QUIET_HOURS`
- 卡死自愈：`DOUYIN_BRIDGE_WATCHDOG_ENABLED/IDENTITY_THRESHOLD/CONSOLE_RESTART/CONSOLE_COOLDOWN_SECONDS`
- 外部依赖：`DTK_BASE_URL`/`DTK_API_KEY`（视频解析）、`BILIBILI_*`
- 媒体：`DOUYIN_BRIDGE_MEDIA_DIR`、`MEDIA_RETENTION_HOURS`

## 6. 加一个新功能的标准流程

1. **先跑通现状**：`curl http://127.0.0.1:8765/api/douyin-bridge`、`/api/status`，`tail -f desktop.log | grep douyin`。知道当前 14 个绑定、任务计数、watchdog 等级。
2. **定位插入点**（按功能类型选）：
   - 新命令/关键词 → `intent.py`（加正则/解析），`service.py` 的分发处
   - 新媒体类型/格式 → `media.py`（识别 + 转码）、`models.py`（StoredMedia 扩展）、`service.py` 的 `_prepare_*`
   - 新发送方式 → `delivery.py` + `backend.send()` 的 action 字段（`media_paths`/`file_paths`/`voice_path`）
   - 新状态/接口 → `service.py: status()` 和 `desktop.py` 的 `/api/douyin-bridge*` 路由
   - 新配置 → `config.py` 字段 + `desktop.py` 设置项（`category: "抖音桥"`）+ `.env.example` + 控制台说明
3. **想清楚失败语义**：桥的铁律是“发送未回读确认就不算成功、不确定不自动重发”。新功能也要遵守，否则会重复投递。
4. **写离线测试**：`tests/test_douyin_bridge_*.py` 用假 chat/假 delivery/假媒体，**不发真实微信、不联网**；新分支至少覆盖：正常路径、失败重试、幂等/去重。
5. **本地跑测试**：
   ```
   $env:PYTHONUTF8="1"; $env:PYTEST_DISABLE_PLUGIN_AUTOLOAD="1"
   .venv\Scripts\python.exe -m pytest tests/test_douyin_bridge_*.py -q
   ```
   再跑全量 `pytest -q` 防回归。
6. **VM 部署**：备份 → scp 源文件 → `py_compile` → `bash scripts/restart-desktop.sh --start-agent --keep-log --port 8765`。重启会拉起新浏览器但复用同一 profile，**不需要重新扫码，也不动微信客户端**。
7. **观测验收**：`/api/douyin-bridge` 的 `chat.connected/calibrated`、`last_error`、`watchdog`；日志关键字 `douyin_bridge_conversation_verified`、`binding_skipped`、`douyin_bridge_job_*`；任务计数不丢；必要时用只读 SQL 查 `douyin_bridge_jobs`。
8. **写记录**：在 `STATUS.md` 加一段：现象/根因/改动/测试/部署/验收/边界。

## 8. 已知坑（改之前先读）

- **页面长驻会“半卡死”**：列表正常、点会话不切换，报 `CHAT_IDENTITY_UNCONFIRMED`；实测健康约 1.5–2 小时后失败率升到 66–90%，且不会自愈，只能重启浏览器/控制台或重载页面。看门狗目前只在“全部绑定连续失败”时升级，半失效时不会触发。
- **身份校验**：打开会话后必须读到目标标题才继续，否则 fail closed；这会导致部分绑定长时间跳过。
- **表情类型**：抖音表情常被识别成 `kind=video`（`ies.fe.effect` 的 WebP），但 `/forward` 只收 `kind=image`；手工补发要自己走 `store_image_bytes → sticker_gif_for_wechat → 文件通道`。
- **静态表情**：单帧 GIF 会被微信当普通文件/图片，项目里会复制一帧做成 2 帧 GIF，才收成原生表情（`local_type=47`）。
- **SEND_BUSY**：微信界面被聊天 Agent 占用时任务回队重试，不要直接标 uncertain。
- **媒体清理**：任务 delivered 后立刻删本地媒体；失败/中断残留按 `MEDIA_RETENTION_HOURS` 清理。调试时注意别把仍被引用的文件删掉。
- **抖音改版**：`chat.py` 的选择器是最脆弱的部分，改版后先跑 `dom-probe`/`calibrate` 再动代码。
